# Navigation V2 · Release Baseline

2026-11-05 按用户要求冻结为 `baseline-v2`，作为后续导航迭代、对比和回退的版本。V1 标签保持原样。功能源码基于 `5fc9ae3e709b5781fb54c744c1ab4f9839072f44`；发布补充说明、参考配置和清单，不替换已经实测的控制算法。

## 功能

- MID-360S 雷达惯性建图、地图保存/重载、定位和实时激光叠加；使用投影观测进行二维导航。
- 网页地图上增加、编辑、删除点位，设置名称、朝向、产品介绍、停留和等待继续；已保存点位先进入编辑状态再修改。
- 单点前往、一键返回、顺序路线、往返和有限循环；到点按配置讲解，再进入下一站。
- 禁行线、减速区、附近停靠、地图版本、续扫、局部更新，以及地图/点位/路线同包备份迁移。
- 实时障碍绕行；无法继续时停车并重规划，保留路线、控制输入和失败原因。地图变化低频收集、按日空闲融合，不每秒重画整图。
- G12 APP 的 E 左档允许导航并显示地图，选点后一次点击开始；中档暂停，操作员主动继续；右档或摇杆接管结束自动任务。取消有效，切回左档不自行续走。
- 机身喇叭优先的导航提示与到点介绍，可设置音量/静音；同类状态去重。
- 前向为主，允许边走边转和原地转向，侧向输入为零；前向增加使用 S 形渐进输入。

## 本次冻结的参数

可直接交给现有 `apply_runtime_geometry` 的参考配置见 [`baseline-v2.json`](../navigation/profiles/baseline-v2.json)。它表达这台已测安装的参数，不能替代另一台机器的身份、安装与实际步态配置。

| 项目 | V2 基线 |
| --- | --- |
| 规划/碰撞机身方块 | 总边长 0.55 m，额外足迹 padding 为 0 |
| 全局、局部实时障碍合并 | 两侧均为 0：真实观测射线可以释放旧占用，新回波仍标记障碍 |
| 点位到达 | 介绍/位置点位 XY 半径 0.40 m；有指定朝向时允许 20°误差 |
| D 前向、转向输入上限 | 0.75 / 1.0；弯行前向目标约 0.6；侧向为 0；本轮倍率 1.0 |
| 原始遥控样本过期时间 | 2.0 s；与健康、命令、RPC、速度反馈各自时效分别处理 |
| 前向增加 | 最大变化率 0.30 输入/s，变化率的变化率 0.40 输入/s² |
| 减速、转向 | 保留原有下降和转向响应；完整归零尚未区分正常制动与保护停车 |

复现这套参数时，把参考配置复制为所选运行目录的 `planning_geometry.json`，现有工作流会在生成 Nav2 参数时读取它。例如先把 `P2_V2_RUNTIME` 设为本机选定的运行目录，再执行：

```bash
install -m 600 navigation/profiles/baseline-v2.json "$P2_V2_RUNTIME/planning_geometry.json"
```

1006 已经使用这组实际参数，本次冻结不重启程序、不重复应用或改动现场设置。独立机器身份、外参、颈部位置和厂家策略配置不由此文件覆盖。

这些速度值是 D 策略的手动等效输入，不能解释成实测 m/s。40 cm 是距目标中心的总到达容差，不是定位误差精度，也不改变碰撞包络。障碍停车、E 开关、摇杆接管与取消保持既有行为，没有增加第二次开始确认或人工验收文件门。

## 实机结果与软件验证

20 个编号点位均有实际到达记录。最初 1、2 号完成后，3 号路段暴露全局/局部障碍合并不一致；修复后从 3 号续行。4 号介绍点又因约 34 cm 距离超出原 30 cm 范围而反复收尾，暂停任务，将上述到达容差改为 40 cm，再恢复同一任务。

从 4 号恢复至 20 号，导航程序自行选路、到点、按配置播报并进入下一站，未再由观察者选路、跳点或补点继续，最后自动停车。续行段记录到 6 次重规划，约 1.4–4.6 s，均自行恢复。此记录是中途修复后的连续完成，**不是一次从 1 到 20 无干预通过**，也没有独立真值证明定位精度或全部物理接触情况。

功能源码 `5fc9ae3` 的 478 项 Python 测试通过；GitHub push [41926395445](https://github.com/lizi-learn/mid360s-lidar-navigation/actions/runs/41926395445) 与 PR [41926406675](https://github.com/lizi-learn/mid360s-lidar-navigation/actions/runs/41926406675) 各 4/4 通过，含原生 ROS/Nav2 集成、地图工具、到点介绍、停留/继续、动态障碍和接管测试。原始失败、旧候选与中途暂停记录保留。仿真不冒充双足实机结果。

实机只读核对了实际 Python/页面、加载的 Nav2 库和独立 D 编译来源；D 编译使用的四个公开输入头文件与发布源码逐项 SHA 一致。Nav2 控制/规划包源码与实际复用的 `1dd17a4` 安装基底一致；仿真输入模型不是实机 D 程序。公开清单见 [`releases/baseline-v2.json`](../releases/baseline-v2.json)，厂家驱动和策略不分发。

## 保留的后续优化

- 途中仍有短暂重规划停车，起步调头仍有停走衔接；下一轮应减少这些停顿，并验证从 1 号开始无需中途修复的整轮任务。
- S 形增加输入已经接入实际 D；正常到点完整归零的 S 形制动意图尚未接通，不能宣称所有停车都已使用 S 曲线。
- MID-360S 当前设备 `time_type=0` 未同步，ROS 头使用主机接收时间，不代表设备采样时间精度。
- 当前发布的导航工作流是二维；实际办公室三维 PCD/变换尚未绑定成已验证的三维导航流程。

## 备份和回退

`baseline-v2` 固定源码、参考参数、依赖版本与本次验证说明。1006 的实际安装配置、地图、点位、路线、二进制身份和服务启动信息另存私有快照，在机器人和开发机各保存一份并核对 SHA；这些材料不进入公开 Release。

V1 仍为 `baseline-v1` → `6479e25f5825b5dbce9e6229a33ad5d564b0649a`。今后的改动从 V2 之后继续，不移动两个基线标签、不覆盖历史失败。换机仍使用新机器身份和独立安装配置；本次冻结没有发送导航目标、重启 D/驱动/颈部或操作电池。
