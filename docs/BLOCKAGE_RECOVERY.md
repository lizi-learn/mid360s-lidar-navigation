# 突然封路后的等待与恢复

运行中的目标因前方障碍或路径暂不可执行而进入 Nav2 恢复等待时，工作台接收真实 BehaviorTreeLog 回执，显示停车与重规划状态。回执保留原始 ROS 日志时间，旧目标、过期日志、普通树运行事件不会启动新的等待。

场地默认策略可在网页管理中调整：短等4秒、最长等待25秒、连续清空1.5秒、重规划决策间隔3秒。这些是软件默认值。实际路径搜索仍会核验全占地；没有通过的绕行不会因为等够时间而变成可通行。无法确认障碍种类时只称障碍，不推断为人群。

- 已有有效绕行路线：观测连续可通行并收到本次障碍之后的新规划，继续前往目标。
- 暂时封路又开放：停止等待，得到新规划后恢复。
- 持续封路：到场地最长等待时间后，结束本次任务、保持零速并提示协助；之后即使开路也不会重新启动已结束的任务。
- E右或摇杆接管结束自动任务；E中暂停后需操作者主动继续。障碍的自动恢复不会撤销人工接管或取消。

为避免底层默认两轮等待先结束，执行每次目标时按当前等待策略生成有界的恢复树。生成树只修改恢复次数和等待节点名称，保持原规划、控制器、目标检查器和取消动作。没有新增人工确认或验收文件。

合成测试使用真实静态走廊、动态射线墙、全局与局部代价图。确认两张实际代价图的横截面均被封闭，才对完全封路期间的零速作断言；开放房间中仅部分可见的大墙不冒充已知完全封路。覆盖封路再开放、持续封路到超时、超时后开放不重启、等待中人工接管。

这些是 ROS/Nav2 与平面射线模型检查。办公室冻结图的后半程卡停、实验性提前减速与真实D策略低速响应仍是独立工作，不能由本项通过推出完整真机导航验收。
