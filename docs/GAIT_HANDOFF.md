# 实验性步态速度接管接口

新增的是本地速度来源仲裁与 APP 后台接入代码。它不包含厂商步态 SDK、策略模型、关节驱动或实机标定，也没有通过完整双足导航验收。

## 接入方式

- `gait_navigation_server.hpp` 在普通线程处理固定长度 Unix `SOCK_SEQPACKET` 请求。实际步态循环调用 `step()`，只读有界快照，不等待网络或文件 I/O。
- `native_operator.hpp` / `native_operator_bridge.py` 复用已核验的 G12 原始遥测，保留接收器原始时间。它们不打开串口、不写原手柄共享内存，也不改变按钮、映射或手动速度缩放。
- 导航 RPC 与真实保护开关使用独立通道。导航客户端不能伪造 E 档位和摇杆介入。
- `gait_transport.py` 必须先取得实际步态循环的 ARM 和零速度接管回执，工作台才发送 Nav2 目标。重连、回左档、摇杆归中都不会自动恢复旧目标。
- 配置 `--gait-socket` 后，APP 会话以步态循环核验的原始手柄样本为准，避免与另一条 ROS 转发链竞争。重复读取不刷新样本时间，ROS 回调延迟也不能延长授权。

SDK 适配器必须提供实际控制器实例、策略代次、接收器身份、D13 实际选中状态、行走状态、硬件保护、标定、地面和定位状态。不能用进程存在、用户请求策略或“健康”客户端字段代替实际回执。

Linux 服务跨用户运行时，服务端 `start(path, client_uid)` 只接受指定用户和 root。目录必须属于指定用户且权限为 `0700`，两个 socket 为 `0600`；同时检查 `SO_PEERCRED`。仅 root 可以指定另一用户，不要开放目录权限绕过接入检查。

## 运动与停车

候选限制保持前向 `0–0.15 m/s`、横移 `0`、偏航 `±0.24 rad/s`。原始手柄及步态循环反馈期限为 100 ms，速度包期限为 300 ms。保留完整包络、停车区、地面、定位和传感器门限。

`motion_buffer.py` 的候选参数为线加速 `0.10 m/s²`、线减速 `0.15 m/s²`、角加速 `0.30 rad/s²`。转向和前进切换等待实际运动反馈收敛；它位于碰撞监控上游。碰撞、接管、过期与未说明原因的零速度立即归零。纯模块支持带明确意图的正常停车缓冲；当前 ROS 适配器不会将 Nav2 的任意零命令当作这种意图。上述参数不是实测制动距离或动态平衡证明。

## 已做的验证与保留的失败

- 131 项 Python 回归覆盖工作流、取消回执、手柄来源、原始时间和缓冲行为。
- 合成 C++ 步态循环覆盖 16 类授权故障、物理中档优先、摇杆接管、回放、重连和零速度握手。
- Python→C++ 本地协议八项合成检查通过；六项跨用户权限检查通过。全部不连接真实执行器。
- 一套私有 ARM SDK 适配器完成编译和不打开硬件的预检；支撑承重、原地待机时采集 233 条真实回执，速度全部为零。未就绪 ARM 被拒绝，零包不获得控制权，重连不自动授权。无导航非零速度、策略切换或行走验收。
- 带地图负载的三次 40 样本比较，档位有效样本分别为 37、38、39。最大原始来源年龄约 108、110、105 ms；100 ms 超时保持生效，发生过期时拒绝导航。普通线程观察回执和优先级隔离有所改善，但此负载检查仍未全部通过，不能作为行走就绪证明。
- 首次安装的模型目录层级和 ROS 导入路径错误已修复，保留失败记录。实机机身标定、近场地面、定位和驱动保护验收仍未完成。
- 原窄门、转身空间和完整控制跟踪失败仍保留；本次接口测试不改变这些结论。

实机录包、地图、模型、厂商源码及机器凭据不在公开仓库中。
