# 现场可通过却规划失败的修复

本次实际定位到两个独立问题：明确指定的 55 cm 方形轮廓，仍被全局配置扩成长停车区；高度切片生成的 LaserScan 声明最大距离 14 m，却包含 17 m、25 m 等有限读数。Nav2 投影会跳过超量程有限值，因而这些实际远回波没有参与射线清除，静态底图中的旧障碍持续影响规划。

`scan_ranges.encode_ranges` 区分了三种情况：近处有效回波保持实际距离；实际测到但超过声明量程的远回波编码为正无穷，交由既有 `inf_is_valid` 清除流程处理；没有切片回波的角度保持 NaN，仍为未知。它不修改源消息时间，也不把空角度假造为已观测空闲。现有障碍标记距离小于清除射线最大距离，远回波不会在量程边界伪造一圈障碍。

每个独立 runtime 可以提供普通配置 `planning_geometry.json`：

```json
{
  "footprint": [[0.275,0.275],[0.275,-0.275],[-0.275,-0.275],[-0.275,0.275]],
  "footprint_padding": 0.0,
  "global_obstacle_combination": 0,
  "local_obstacle_combination": 0
}
```

这份配置保存本机明确指定的轮廓。新工作流程启动时会应用它，即使旧 Console 仍缓存着旧参数生成函数，切地图后也能保留同一轮廓。没有这份配置时沿用输入参数，不构成任何人工确认或启动门。

组合方式 0 让实时障碍层已观测的空闲格可以覆盖底图的旧占用；实时命中仍标记障碍，未知格保持未知。原始地图文件保留，不通过擦除地图、缩小指定轮廓、修改源时间或停用障碍源获得结果。实际部署需核对所选传感器的观测、清除范围与地图语义，不能把此机器的轮廓当成其他机器的标定。

P2 的滚动局部图加入静态底图后，也必须保留相同的实时射线合并方式。否则全局图已扫空的旧占用，在局部图仍按最大值保留，产生“路线通过、控制拒绝”的循环。P2 局部图默认使用方式0；运行配置可以显式保存两层的方式，工作流程重新生成参数后仍一致。无当前射线的旧占用、静态未知、当前命中以及最后应用的禁行／地图边界过滤继续保留。低频地图学习与原始底图不因这一实时合并而改写。

APP 默认按前进方向到达点位，指定朝向为可选项；初始定位操作仍采用明确朝向。单次开始、E 档位、摇杆接管、取消和障碍停车语义不变。

实际修复后，41 帧扫描中超量程有限值为 0，出现 247 个已观测远射线样本，并保留 1747 个 NaN 未知角度样本。此前受旧障碍影响的同一目标生成了 67 个路径点。原始地图未改，驱动、策略、传感器进程保持原身份；这次仅验证实际传感器与真机规划，没有发起真实导航行走。仅加长规划时间、改运动基元或改终点容差的尝试没有修复该目标，失败记录保留。

本次运行包以既有实机协议版本为基础，合入以上修复及已验证的缓冲源年龄修复；不替换运行中的 RL 或 EtherCAT 程序。仓库中另有原生速度闭环候选，不能把该候选的模型验证称为本次已部署或真实行走通过。
