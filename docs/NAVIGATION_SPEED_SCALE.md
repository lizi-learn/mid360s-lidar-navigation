# 导航 0.5 倍速

G12 APP 的实时地图使用现有导航工作台视图，新增 **0.5倍速 / 1倍速** 按钮。倍率统一作用于导航的前进、横向及转向角速度目标，`z` 在这里表示偏航角速度，横向仍遵守前向导航的零横移限制。原始摇杆、E 档位及手动速度映射不修改。

P2 候选配置默认选择 `0.5`。原前向目标上限 `0.15 m/s` 对应输出上限 `0.075 m/s`，原偏航目标 `±0.24 rad/s` 对应 `±0.12 rad/s`；它表示倍率，不是 `0.5 m/s`。

倍率在最终前向速度门内应用，之后仍需经过原有步态控制权核验。下调倍率时已有前进和转向输出同步按比例降低；恢复 1 倍速时保留加速缓冲。停车、取消、手动接管及过期故障仍立即归零，选择倍率不会开始或恢复导航。

模型响应补偿的内部策略输入与物理导航目标是不同量。应先缩放导航目标，再做经确认的响应映射；不能直接把补偿后策略输入乘半并称为机身半速。当前模型补偿仍未作为实机速度标定安装。

沿用现有同源网关接口，无需给 APP 增加新的目的地址或电机接口：

```json
POST /api/speed
{"speed":0.15,"velocity_scale":0.5}
```

响应包含 `speed_m_s`、`velocity_scale` 和 `effective_speed_m_s`。省略 `velocity_scale` 保留当前倍率，允许值为 `0.5`、`1.0`，其他值拒绝。状态中的 `speed_cap` 保留名义滑块值，`effective_speed_cap` 表示应用倍率后的上限。

五项新增回归检查覆盖三路输出比例、起步及转向缓冲、倍率切换、保护零输出，以及实际 Console 方法生成的消息进入实际 Gate 回调；完整 Python 回归为 170 项。APP 视图从现有机器人导航服务读取，升级成功仍需核对机器人实际服务版本和回执，不能把本地源码通过称为已部署。
