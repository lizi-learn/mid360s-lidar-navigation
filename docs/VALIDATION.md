实际运行平台：RK3588 / Ubuntu 22.04 / ROS 2 Humble，Nav2 1.1.20、SLAM Toolbox 2.6.10。下面分别记录平面仿真、动力学模型和真实数据回放，不能相互替代。

| 检查 | 结果 | 边界 |

| RPP + 前向格点规划 | 三个导航目标均成功，含转身后向前走 | 不允许横移或倒退 |

| 真实办公室录包回放 | 6,341/6,341 帧发布；地图和位姿图保存成功 | 使用录制 LIO 位姿先验，无外部真值 |
| 实时雷达 + 办公室地图 | 指定近似初始位置后定位就绪，约 2 m 目标生成 41 点路径；另一个目标被障碍代价拒绝 | 静止、有初始位姿先验；前方地面支持观测不完整，保持禁止执行 |

| 回归 | 38 个 Python 单元测试、C++ 速度租约协议检查通过 | 不替代 ROS 集成与实物测试 |

最终动力学闭环三个目标的模型真值位置误差为 [0.144, 0.086, 0.21] m，角度误差为 [4.2, 2.1, 1.1]°。导航输出最大前向速度 0.25 m/s、最大角速度 0.24 rad/s、侧向指令恒为零；碰撞计数为零。约 147.8 s 模拟中，骨盆最低 0.851 m，最大横滚 2.73°、俯仰 7.30°，未触发跌倒中止。模型实际存在踏步横向摆动和速度纹波，不能把指令限速等同于逐时刻机身速度上限。

故障测试包含速度上限下调、前方地面消失、扫描中断、里程计中断、动态障碍停车以及侧向错误指令拒绝。这些检查测的是**输出命令归零**，不是实物停止距离或双足稳定裕量。

动力学实验使用当前安装程序的 P2 AMP 策略和对应模型，另行修复了模型的资源路径并加入合成墙体。没有调用电机驱动或厂商共享内存。模型的速度响应存在明显死区，闭环测试采用仅仿真的响应补偿；该补偿不是实物标定，模型也未覆盖本机雷达与支架的准确质量、惯量和整机编码器零位。厂商资产未随开源代码分发，公共平面仿真可复现，P2 专有策略实验需要使用者自行提供合法资产。

办公室回放产生 950 × 616、0.05 m 分辨率地图，约 47.5 × 30.8 m。它使用原始点时间与录制 LIO 位姿进行运动补偿和高度切片，6341 帧局部地面拟合均完成。启用 SLAM Toolbox 回环并保存位姿图，不代表发生了经过独立真值验证的回环纠正，也不能将地图末端误差当作厘米级定位认证。

测试中发现并修复了定位状态为 NumPy 布尔值时消息序列化导致速度门退出的问题；退出后租约到期让模拟步态归零。另观察到 AMCL 随机粒子恢复造成定位发散；最终配置禁用随机恢复，定位不可靠时等待人工重新设置初始位置。模式切换清空旧地图与定位状态，速度门等待新定位消息。上述失败没有被计入通过结果。

实机适配测试修复了旧水平点云话题仅声明而未发布的问题：现在直接读取 FAST-LIO 点云并在适配器内按当前会话对齐。前方六个地面支持区尚未全部观测到，不能据此允许实际前进；需实测架子遮挡、安装视野与机身外参。

完整使用方法和接口边界见 [前向导航工作流](NAVIGATION.md)。真实行走、实际停止距离、机身外参、准确足迹、复杂地形和故障下的双足平衡仍未验收。

## 2026-10-29：原传感器链路的现场记录

日期：2026-10-29。下面是内部实机测试摘要；现场地图、照片、设备身份、私网配置和原始录包未公开，因此不能用本页独立复核绝对定位精度。公开版本另提供合成演示及可复现的单元测试。

## 已观察到的实机结果

- MID-360S 倒装、无深度相机，RK3588 / ROS 2 Humble；人工推架一圈约 95.4 米，检测到移动段约 139 秒，最远离起点约 40.1 米。
- 不压缩 SQLite 录包约 2.67 GB、10 个分片；停止录制后逐个 quick_check、SHA-256 和 ROS 顺序读取通过。
- 原始雷达 6,341 帧、雷达 IMU 126,827 条、机身 IMU 122,922 条、里程计 6,340 条。文件可读不等于硬件采样完全无缺失。
- 里程计约 10 Hz，最大源采样间隔 108 ms；消息源时间到录包接收的延迟中位 40 ms、99%分位 60 ms、最大 137 ms。本圈未见时间回退或超过当前跳变门限的位姿跳变。
- 起终点约差 12.5 cm、9.2°，但实物仅近似返回，因此**不称为闭合漂移精度**。
- 操作者报告走完后继续静止约 211 秒，X/Y 峰峰变化各约 1.2/1.1 cm。没有外部位置真值，不是厘米级精度认证。

## 已做的修正

1. 原生累计地图曾每秒重复发布全部历史点云，负担随时间增长。关闭此可视化输出，保留 FAST-LIO 内部地图和有界的页面累计图。
2. FAST-LIO IMU 订阅队列从 10 增到 400；补丁与上游版本锁定。短缓存曾可能在长回调期间丢失 IMU 历史，但不能据此断言它是之前跳变的唯一根因。
3. 按消息源时间判断过期，避免迟到消息刚接收就显示实时；明显跳变会锁定路径预览，继续保留诊断录包。
4. 采集期间取消实时 zstd 压缩。旧压缩录包曾正常退出并生成 metadata，但离线读取/完整性检查失败；当前原始分片方案经过实际分片切换与回读自检。
5. 活动 SQLite 被在线查询时曾引发写锁冲突、录包退出；已改为**结束后**检查，不再以在线数据库查询做采样率检查。

这些修正后的一圈没有重现之前约 0.7 米的静止跳变；这不证明长期问题已经彻底消失。

## 尚未解决或未验收

- 固定全局 Z 门限可能漏掉倾斜或高度变化的地面。本圈稳健拟合地面相对初始坐标倾角约 0.92°，真实坡度、初始重力对齐与高度误差尚未分离。
- 机身 IMU 曾出现约 1.505 秒的采样间断，设备时间无效。移动时相对航向差 RMS 约 0.44°，停车后两路航向差继续扩大，末端约 3.5°；它还不能直接修正雷达或参与融合。
- 当时尚无闭环图优化、地图重定位、地图重载与失定位恢复验收；新增仿真与回放工作见上节，实物验收仍未完成。
- 没有雷达到机身/颈部外参、真实机器人足迹、执行层限速与控制验收。
- 通用构建脚本尚未在第二台空白机器完成端到端测试；已有原机器的构建验证不能替代新机器验证。
