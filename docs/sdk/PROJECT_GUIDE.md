# P2 导航项目完整手册

**Navigation V2 baseline · NavBridge SDK 0.1.0 · 2026-11-05**

面向开发、部署、运营与云平台接入。当前工作流用于平地双足雷达导航、导览与产品介绍。V2 是固定的导航基线；本次 SDK 和文档站是后续扩展。历史文档中的实验参数按其日期保留；当前这台 P2 的参数以本手册与 `docs/BASELINE_V2.md` 为准。

## 1. 项目目标与交付结构

让机器人能建图、定位、选点行走、避障、按规定路线导览，并在到点后朝向产品、介绍、停留或等待访客继续。电脑网页负责精细管理，G12 APP 负责现场执行和人工接管。SDK 把业务程序与底盘区分，同一业务可以选择 P2 或 WATER 适配器。

| 目录 | 内容 |
| --- | --- |
| `navigation/` | ROS/Nav2 工作流、会话、导览任务、地图工具、网页与声音 |
| `navigation_sdk/` | Python 客户端、HTTP 网关、P2/WATER/mock provider、WATER 兼容入口 |
| `clients/typescript/` | Node/TypeScript 客户端、类型声明与实际 HTTP 合同测试 |
| `api/navigation.openapi.json` | OpenAPI 3.1 机器可读接口 |
| `docs/sdk/` | 本手册、接入指南、兼容矩阵 |
| `examples/sdk/` | Python、TypeScript、WATER 示例 |
| `tests_sdk/` | 本地 TCP/HTTP、任务与签名合同测试 |
| `website/` | 静态文档站源码与合成导航演示 |
| `releases/baseline-v2.json` | 冻结导航基线的来源、参数与验证记录 |

公开仓库不包含厂家电机驱动、私有 RL 策略、办公室地图/录包、现场话术音频或凭据。实际安装配置与场地包单独私有备份。

## 2. 系统架构与数据流

传感器链：MID-360S 点云与内置 IMU → Livox ROS Driver2 → FAST-LIO 雷达惯性里程计 → 重力对齐、局部地面拟合与高度切片 → 导航虚拟扫描、里程计和 TF。

导航链：SLAM Toolbox 建图/回环与位姿图保存；重载地图后由 AMCL 定位；Nav2 前向规划与 RPP 跟随，加入本项目的通道、转向响应、障碍和任务处理；命令由既有步态接管适配器送到 D 策略。普通弯道允许边走边转，必要时原地转向，侧向输入为零。

业务链：网页/G12 或 SDK → Console 会话和导览 Mission → 导航动作 → 真实完成回执 → 方向/介绍/停留/等待 → 下一站。语音准备和播放独立，不阻塞控制线程。SDK 是独立伴随进程，不直接操作电机、不取代原有 E 开关和摇杆控制权。

统一 SDK 可以选三个 provider：P2 使用 Console HTTP；WATER 使用 TCP 31001 原始接口；mock 是明确的合成合同夹具。WATER 兼容入口将老程序已支持的命令子集转到同一 P2 会话。云迹云端订单属于另外的业务层。

## 3. 当前版本、能力与实际验证边界

V2 功能包括：雷达惯性建图、地图保存重载、定位、实时激光、常用点位、路线巡游、介绍与方向、停留和等待、禁行线、减速区、附近停靠、地图版本、续扫/局部更新、低频每日地图融合、任务回放和场地包迁移。

实机 20 个点位均有到达记录，但原轮在第3点前修复障碍合并，在第4点暂停调整到达容差；从第4点恢复至第20点后自动完成。这不是从1到20一次无干预通过。续行中6次约1.4–4.6秒重规划自行恢复；原始失败保留。SDK 本次没有启动真实运动或调用云迹生产服务。

| 项目 | V2 当前安装配置 |
| --- | --- |
| 机身导航方块 | 总边长55厘米，额外 footprint padding 为0 |
| 讲解/位置点到达 | XY 半径40厘米；指定方向允许±20° |
| D 输入 | 前向上限0.75，转向1.0，弯行前向约0.6，侧向0 |
| 本轮倍率 | 1.0；已有半速模式按实际选择生效 |
| 原始遥控样本超时 | 2.0秒，与命令、健康、速度反馈/RPC时效分别处理 |
| 前向加速 | S形增加，变化率0.30输入/秒，变化率变化0.40输入/秒² |
| 减速与转向 | 保留原有下降/转向响应；尚未接通完整正常停车S形制动 |

D 值是手柄等效输入，不是已标定的米/秒。40厘米是目标范围，不是定位精度。当前为二维导航；三维点云可作为观测/展示资产，尚未验证完整办公室三维地图与全高度路径规划。MID-360S 当前 time_type=0，ROS 头来自主机接收时间，不代表设备采样时刻已同步。

## 4. 环境、依赖与安装

导航环境：Ubuntu 22.04 / ROS 2 Humble；1006 为 ARM64。SDK 纯 Python 要求3.10+，不依赖 ROS，不增加 Python 第三方运行包。TypeScript 客户端要求 Node18+ 或具备 fetch 的环境。文档站是静态资源，不运行导航进程。

传感器构建锁定依赖：Livox-SDK2 `c0796f0`、livox_ros_driver2 `2144554`、FAST_LIO `cc3c9e8`，完整 SHA 在 `scripts/build-deps.sh`。项目独立模块 MIT；FAST-LIO 补丁沿上游 GPL-2.0，见第三方许可。

```bash
sudo apt-get install ros-humble-navigation2 ros-humble-nav2-bringup \
  ros-humble-slam-toolbox python3-numpy python3-scipy python3-yaml \
  build-essential cmake libeigen3-dev libpcl-dev libjsoncpp-dev \
  python3-colcon-common-extensions ros-humble-pcl-ros \
  ros-humble-pcl-conversions ros-humble-rosbag2
bash scripts/build-deps.sh
bash scripts/build-nav-controller.sh
```

这是构建说明，不会自动部署厂家 D/电机程序。空白设备仍需按实际系统检查依赖，不能把1006构建通过当作任意平台已验证。

安装独立 SDK：

```bash
python3 -m venv .venv-sdk
. .venv-sdk/bin/activate
python -m pip install ./p2_navigation_sdk-0.1.0-py3-none-any.whl
navbridge --backend mock --water-bridge-port 31001
```

源码开发也可 `python -m pip install .`。文档站下载项附 SHA256，包名以实际下载文件为准。网关任务日志目录只用于本实例；同一目录不能启动第二个实例。

## 5. 网络、机器身份与传感器

每台机器人使用自己的机器身份、安装 ID、传感器外参与颈部位置。换机不能把旧标定或地图中的实时定位状态当作新机已核验。1006 现场雷达在 eth2，历史示例雷达192.168.1.196、主机192.168.1.100/24；这些是该安装记录，不是全系列默认地址。

使用专用传感器网卡，不改电机总线网卡。检查实际链路、地址、路由和点云/IMU来源后再写入本机配置；`scripts/configure.py` 从示例生成传感器文件，不包含全机网络管理或电机控制。

| 服务 | 默认位置 | 用途 |
| --- | --- | --- |
| 传感器预览 | localhost:8920 | 点云、雷达/机身IMU记录与状态 |
| 导航 Console | localhost:8930 | 建图、定位、Nav2与导览工作台 |
| 本项目电脑转发 | localhost:18930 | 过去现场使用的转发入口；以当前转发配置为准 |
| SDK HTTP | localhost:18940 | 统一客户端接入 |
| WATER 兼容入口 | localhost:31001（显式启用） | LF/CRLF profile；不是HTTP |
| 公开文档站 | Cloudflare Pages | 资料与下载，不连接机器人 |

远程业务进程优先通过现有私网/隧道访问伴随网关。HTTP远程绑定可用环境变量 NAVBRIDGE_API_KEY；不要把凭据放在公开网页。WATER 兼容入口本身没有厂商鉴权合同，本版仅绑定loopback，可通过私有转发接入。

## 6. 建图、保存、定位与地图重载

先启动传感器工作流，再启动实际安装的导航 Console。以下为公开源码入口示意；现有机器以自己的服务配置为准，不重复启动相同端口/ROS域：

```bash
bash run-stack.sh
# 另一个终端
export P2_LIDAR_ALIGNMENT="$PWD/runtime/map_alignment.json"
bash navigation/console.sh
```

在工作台选择新地图名称并开始建图，沿可观察通道采集；回到明确地面位置/朝向检查闭合。保存后应包含 mapped.pgm、mapped.yaml，以及可用于续扫的 mapped.data / mapped.posegraph。只有PGM/YAML不能声称具备位姿图续扫。

载入已保存地图进入导航，地图上检查机器人当前位置、朝向与实时激光是否一致。需要校正时使用定位工具设置/拖动初始位姿，不能把屏幕箭头直接当物理真值。地图切换会改变点位上下文，SDK任务也会被标记为地图已变更，而非沿旧坐标继续。

原始录包先结束写入再检查完整性；不要把正在写的SQLite分片当完整可回放录包。地图文件、原始数据和派生版本分开保留，方便还原。

## 7. 一张地图完成点位和产品管理

电脑打开 Console 的 `/reception`。同一页可选地图、点击新增点、填写名称、可选方向、产品、话术、停留时间和是否等待访客继续。名称不能空白；同地图NFKC规范化、去首尾空格及大小写后不重名。

已保存点位默认锁定：点击只选中，拖动只平移地图。先点“编辑点位”才能修改或删除，保存后锁定；取消编辑恢复原内容。新增草稿可编辑，首次保存后锁定。别的窗口已保存新修订时，服务端返回版本冲突，刷新合并后再保存，不悄悄覆盖。

“前往此点测试”使用已保存点的介绍/方向；“点图导航”模式下，点击已存点执行该点，点击空白地面使用临时位置，不新增后台点位。选择目标后一次开始，SDK调用也只派发一次，不加入第二次人工确认。

介绍优先用点位覆盖话术，否则用所选产品默认介绍。未设置方向的点不额外对正；设置方向后在V2容差内即可完成，不为几厘米/几度反复微调。

## 8. 规定路线、巡游与到点互动

管理员在同图按顺序加入站点，上下移动、删除、设置有限循环。空路线可保存为草稿；执行路线必须有站点。普通途经点连续通过；有方向、介绍、停留或等待的站点执行到点动作。

流程是：指定路线 → 到点朝向 → 介绍产品 → 停留或等待继续 → 下一站。任务开始固定本轮内容快照，运行期间的管理编辑用于下一轮，不突然改当前路线和话术。访客等待时操作员点击“继续下一站”；暂停后主动恢复。取消结束本轮，不自动进入下一轮。

规定路线保留途经顺序，自适应路线保留介绍点顺序，并按已有有效连接/门证据选择路线。临时障碍仍由实时规划绕行，不通过编排器强行直穿。SDK的 `route(route_id)` 使用后台已保存路线；本版WATER兼容层尚未实现 `markers/count` 临时巡游，不把它暗中当单点。

## 9. 操作员、G12与控制权

E最左允许导航并切实时地图；中档暂停、速度归零，主动继续后恢复；右档手动优先，或摇杆介入，结束自动任务。切回左档只允许新的显式开始，不自动续走。取消导航与障碍停车保持原行为。

G12 APP用于选择点位/路线、开始、暂停、继续、取消和查看状态；电脑网页负责文字录入、地图标注、精细编排、备份与回放。右上状态使用实际D/档位回执，不把网页按钮已点当作策略已接收，更不当作实际迈步。

SDK使用同一控制权。任务受理后仍可能因人工接管、地图切换、真实执行故障或障碍无法绕过而结束。P2 SDK扩展用generation/run_id/epoch/map_id比较控制引用；旧任务的cancel不能误取消用户在APP刚启动的新任务。

## 10. 实时避障、等待与门的变化

前方突然完全挡住时：实时障碍输入触发减速/停车，尝试规划绕行；有可行路则继续，无路则等待/重规划并给出原因，超过当前策略等待范围后停止并提示。不会只因地图曾经有路就继续撞过去。

当前开发运营默认短等候4秒、连续等候上限25秒、恢复稳定1.5秒、重复规划间隔3秒；这些是可调运营参数，不是用户规定，也不保证所有Nav2故障都恰好等满25秒。故障日志应区分等待、无路径、执行失败、输入过期和人工接管。

管理员可标注门叶条带与连接。开门需真实射线完整覆盖的开放证据；部分视野、无回波和未知不直接证明开放。关闭回波撤销旧开放状态；地图重载或门几何变化清除对应记忆。自适应路线在捷径收益足够时切换，减少反复折返。转向时仍核查实际完整导航轮廓和障碍，不清回波制造“通过”。

## 11. 禁行、减速、附近停靠与地图学习

管理页“地图标注”绘制禁行线/多边形与减速区。禁行在全局和局部代价图同时生效，原地图未知边界仍保留，不能绕到楼梯或地图外。减速区配置倍率，退出后恢复原选择值；它不是重新标定D策略物理速度。

目的地占用时可选择附近停靠候选。没有实际路径验证时明确显示planner_verified=false；用户选择后仍由实际规划执行，不把目标偷偷移到任意空地。原保存点位不被本次停靠覆盖。

固定底图不每秒重画。低频学习最多每秒取一帧实际扫描，路过旧占用时至少8个不同源时刻支持真正扫通，才进入待融合证据；未知和遮挡不补空。默认每24小时最多空闲融合一次，也可安排“空闲时融合已观测变化”，不取消正在执行的导航。

原PGM不改写，已融合/待融合证据保存在绑定原始地图摘要的 observed-map.json；显示和规划使用一致变化。今日临时人群继续由实时避障处理，不永久缩小底图。恢复原底图会先保存版本，再清除派生学习。大改装修使用局部更新或重新建图。

## 12. 地图版本、续扫、备份与换机

地图工具支持版本保存/恢复、加载真实位姿图续扫，以及限定区域的局部栅格更新。区域外不改，未观测格不抹掉旧数据；序列化图仍保留本轮扫描，不能宣称位姿图也被裁成区域。

场地ZIP包含地图、可用位姿图、点位、路线、产品话术、门、标注、地图学习证据与逐文件SHA256。传输分片和整包校验后才导入，目标使用新地图名和来源安装ID。地图包不包含机器人电机/策略配置、标定、实时定位、凭据；生成语音在新机器按话术重新准备。

换机先部署匹配架构依赖与独立配置，再导入场地和校正定位。不要把1006的颈部编码器零位或雷达外参直接作为1003/1005已测结果。SDK业务点名可保持，但map/floor转换必须显式配置。备份保留公开源码版本、私有安装快照和各自SHA，V1/V2标签不移动。

## 13. 统一 SDK：方法、任务与错误

| 方法 | 语义 |
| --- | --- |
| capabilities/status/maps/markers/routes | 查询真实能力与状态；字段缺失保留未知 |
| move(marker 或 x/y/theta) | 只导航；theta省略表示不指定终点朝向 |
| visit(marker) | 导航并执行该点方向、介绍、停留/等待 |
| route(route_id) | 执行已保存路线 |
| task(task_id) | 读取这一个任务，不把当前全局任务替代它 |
| pause/resume/continue_visit | 按provider能力控制导览，不自动越过人工接管 |
| cancel(task_id) | 条件取消此任务；P2旧任务引用不能停止新任务 |
| stop() | 明确全局当前导航停止，不是电机/电池关机 |
| save_marker/delete_marker | 点位同名upsert/删除；P2路线引用不会被静默删除 |

HTTP入口以 `/v1` 开始。任务POST可带 `Idempotency-Key`，同键同内容返回原任务，同键不同内容409；状态目录SQLite持久记录派发意图。断线导致结果未知时不自动重发，重启也不复活自动任务。查询旧任务、核对原导航状态后由业务决定后续操作，避免一次下单触发两次走路。

状态：dispatching → accepted → running；途中可blocked/paused；导览可presenting/waiting/dwelling；终态succeeded/failed/cancelled/interrupted/unknown。accepted不是到达；介绍点导航到达也不等于全部讲解结束。查询暂时失败保持最后状态并标 observation_stale，不能用旧观测证明新近成功。

常见结构错误：INVALID_ARGUMENT；未接能力：UNSUPPORTED_CAPABILITY；同名解析失败：MARKER_NOT_FOUND/AMBIGUOUS_MARKER；并发：TASK_BUSY/IDEMPOTENCY_CONFLICT；上游结果未知：UPSTREAM_UNCERTAIN。未知结果不自动重试。wait超时/客户端Abort仅停止等待，不会自行取消导航。

## 14. WATER 和云平台迁移

WATER是TCP31001上的裸URI与异步JSON，不是HTTP；响应按增量UTF-8和JSON对象解析。uuid用于请求关联，task_id用于任务关联。兼容服务明确使用LF/CRLF请求分帧；原厂手册未定义结束符，需与同事具体SDK核对。

导航、普通点位CRUD、状态/订阅和部分通知已实现。多点markers/count、参数覆盖、轮速、轮式自由停止、回充、电梯等未实现时明确拒绝。P2没有电量、充电、楼层来源时不填100%、false或假楼层。完整矩阵见 `COMPATIBILITY.md`。

云端Open API另有鉴权、订单、门店点位和业务回调。已按官方历史代码完成标量HMAC签名工具和向量，未实现云端订单服务。推荐同事在云平台“设备驱动/导航provider”层接统一SDK；若当前使用厂商特定REST云服务，则按其调用清单另补业务适配，不把本地导航API谎称为同一云服务。

## 15. 声音、运行记录与排障

机身喇叭优先。导航开始、暂停/取消、被阻挡、重规划、失败采用轻声短句和去重；产品介绍在后台预生成本地WAV，到点只播放。丢失音频或播放失败会显示文字并等待操作员继续，不记作已经播完。

任务事件与约5Hz采样异步记录位置、控制决策、实际回执、稀疏障碍和失败原因；源时间分别保存，缺失为null。不是全量点云/每个控制周期，也不是物理真值。SDK日志的created_at/observed_at是主机业务记录时间，不能拿来冒充雷达采样时刻。

| 现象 | 先核对的具体来源 |
| --- | --- |
| 已受理但没走 | 任务阶段、实际D/控制回执、E/摇杆、动作接收结果；不要只看HTTP200 |
| 规划失败/途中停车 | 当前全局/局部障碍、完整轮廓、地图未知边界、途经点与失败原因 |
| 终点卡停 | 当前目标类型、到达容差、方向输入、动作真实终态和介绍等待阶段 |
| 地图“脏点” | 静态底图旧占用、实时新回波、射线清障及待融合证据，分别检查 |
| 转向波浪/贴边 | 实际路线、定位方向、输入响应滞后与局部障碍，不直接缩小轮廓掩盖 |
| SDK任务unknown | 派发回复是否丢失、网关是否重启、WATER状态有无任务ID关联 |
| 没播报 | 音量/静音、音频资源、当前任务epoch、播放回执；不重启全身控制排声音问题 |

## 16. 性能、部署和回退

SDK独立进程，业务状态建议1–2Hz轮询；摘要接口避免每次拉整张栅格。兼容订阅最高2Hz，TCP消息/HTTP body/任务日志有界输入。SDK不在控制回调里联网、合成语音或同步写地图。静态文档站仅首次加载资源，不增加机器人CPU负载。

新SDK目录不替换Livox安装使用的sdk/目录。单个网关状态目录通过进程文件锁防止双开；重启后未完成任务标unknown，不盲目继续。长期任务数据库需要按业务保留周期外部归档，首版不擅自清历史。

Console增加可选 `/api/sdk/version` 与条件任务引用，不改原APP请求格式；原生控制仍由现有链路执行。软件更新安排自己的服务/目录，不重启共享驱动cgroup。此次SDK交付没有替换实机运行版。

回退SDK可停止自己的网关进程，保留日志，使用旧应用；V2基线始终固定。导航程序回退依据私有快照与baseline-v2源码，不用新SDK标签覆盖历史基线。

## 17. 验证方法与后续接入

本版自动测试包含真实loopback HTTP/TCP连接、UTF-8每个切分点、粘包/半包、订阅事件、任务受理与终态、重复请求并发、重启不重放、取消引用、marker保存、未知数据、官方签名向量，以及项目实际会话的附加比较控制。TypeScript测试启动Python网关进行跨语言调用。所有这些是软件合同验证，不是同事固件互通或真机运动验收。

下一步针对同事当前SDK的去敏线包补兼容profile：确认传输方式、固件版本、结束字节、调用清单、map/floor映射、状态字段和完成判断；将样例固定成测试。需要的客观接口差异应实际实现，不用人工验收文件或重复确认替代开发。

后续算法重点仍是减少短暂停车、验证正常S形制动、优化原地转向/弯行衔接，以及从首点开始连续整轮验证。3D展示、全高度净空、电梯/自动门/回充属于有实际数据/硬件后再增加的能力，不在本SDK首版假装已接入。
